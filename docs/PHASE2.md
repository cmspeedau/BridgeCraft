# Phase 2 — Thumbnails & Cache

Implemented in `bc-thumbnails`:

- **Decoder** (`decoder.rs`): decodes PNG/JPEG/GIF/WebP/TIFF/BMP via the `image` crate, converts to RGBA8, and downscales so the longest edge fits the requested size (aspect-preserving box filter via `imageops::thumbnail`, shared `thumbnail_from_rgb`/`thumbnail_from_rgba` helpers). Dispatches by extension to PSD, Illustrator, video, PDF and camera-RAW decoders below, and exposes `can_thumbnail` so callers only queue files the machine can actually decode.
- **Video** (`video.rs`): extracts one representative frame from common video containers (MP4/M4V/MOV/MKV/WebM/AVI/WMV/FLV/MPG/MPEG/M2TS/MTS/3GP/3G2/OGV/TS/VOB) using a **locally installed `ffmpeg` binary** through `ffmpeg-sidecar`. FFmpeg is spawned per clip with `-ss 1` (falling back to `0` for clips shorter than a second), builds a single frame scaled with `scale=<edge>:<edge>:force_original_aspect_ratio=decrease`, and pipes raw RGBA back on stdout — no temporary files and no full-resolution decode. FFmpeg is **not linked or bundled**: when no binary is on `PATH` (or next to the app), `video::is_available()` is false and `decoder::can_thumbnail()` reports video files as unsupported, so browsing a folder of clips does not spam failures. The probe is cached once per process.
- **PDF** (`pdf.rs`): renders page 1 of a PDF through a **locally available Pdfium library** bound dynamically with `pdfium-render`. The page is scaled by `max_edge / longest_page_edge` (points are 1:1 pixels at 72 dpi), capped at the requested edge, with image smoothing on and annotations/form data off. Library discovery checks `PDFIUM_PATH` (file or directory), the executable's directory, common install directories, then the OS loader; the first successful binding is kept in a process-wide `Mutex<Pdfium>` (Pdfium initialisation is global and expensive). Pdfium is **not linked or bundled**, and when it cannot be loaded PDFs are treated as unsupported instead of failing per file.
- **PSD / Illustrator** (`psd.rs`, `ai.rs`): PSD thumbnails are extracted from Photoshop image-resource blocks 1033/1036 (embedded JPEG or 24-bit uncompressed RGB), with validated dimensions and bounded resource/pixel sizes; unsupported/corrupt resources return an explicit PSD error. PDF-compatible `.ai` files are rendered through the existing optional Pdfium PDF path, while PostScript-only `.ai` files return an explicit unsupported error. This uses the existing `image` crate and adds no dependencies.
- **Camera RAW** (`raw.rs`): binds to a **user-installed LibRaw** at run time with `libloading` (no linking, no bundling, no build-time headers). Discovery checks `LIBRAW_PATH` (file or directory), the executable's directory, common install directories, then the loader path, trying plain and versioned sonames. Decoding opens the file, prefers the camera's embedded preview (unpacked with `libraw_unpack_thumb` and rotated to match the processed aspect when the preview is in sensor orientation), and falls back to a full `libraw_dcraw_process` render at 8 bits when there is no preview large enough — the render also applies the camera flip. Every call is serialised behind one process-wide mutex because LibRaw's plain build keeps global state. When no library loads, RAW files are treated as unsupported instead of failing per file.
- **SQLite cache** (`cache.rs`): rows keyed by `(path, max_edge)` with `(mtime_ns, size)` validation — any file or size-tier change invalidates automatically. `put` upserts; `prune_missing` removes rows for deleted files.
- **Orchestrator** (`lib.rs::load_or_generate`): cache-first with graceful fallback to decode when the cache errors; cache writes are best-effort and never fail the caller.
- **bc-ui**: opens `.bridgecraft-thumbs.db` in the CWD, generates thumbnails for the browsed directory at 256px, logs hit/miss/failed counts, prunes stale entries on startup, and reports at launch whether video/PDF/RAW thumbnails are enabled. Failed decodes are remembered for the current listing and retried after a refresh or folder change. `--rebuild-cache` uses `can_thumbnail`, so video, PDF and RAW files are included only when their runtime decoder is available.

## Verified
- Decoder max-edge + aspect-ratio tests
- Video extension classification; frame extraction from a generated 4:3 clip (100×75) and a sub-second clip (first-frame fallback); corrupt input reports `ThumbError::Video`
- PDF extension classification; page rendering from a generated one-page PDF (100 px long edge, portrait aspect preserved, red content rectangle and white margin visible); corrupt input reports `ThumbError::Pdf`
- PSD extension classification; image-resource parsing tests cover embedded JPEG, 24-bit RGB with padded rows, missing/malformed/oversized previews, plus PSD-to-thumbnail downscaling. Illustrator PDF/PostScript detection and PostScript-only error behavior are covered by inline-fixture unit tests.
- Camera RAW extension classification; **real camera files** (a Canon EOS-1D X `.dng` and a Raspberry Pi `.raw` from raw.pixls.us, CC0) decode to correctly oriented, full-colour, white-balanced thumbnails; corrupt input reports `ThumbError::Raw`. The sample test is gated on `RAW_SAMPLE` so no binaries live in the repo; CI fetches a checksum-pinned CC0 sample.
- Cache roundtrip, invalidation on mtime/size/max_edge, prune tests
- End-to-end cache-hit behavior test (`cache_roundtrip_and_invalidation`)

Video, PDF and RAW tests generate their own fixtures and skip with a log line when the corresponding decoder is not installed, so the suite stays green on machines without them.
